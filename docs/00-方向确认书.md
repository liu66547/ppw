## 二、网站定位与目标

**一句话定位**：一份「可交互的、带证据链的」简历 —— 让面试官 30 秒看懂我会什么，3 分钟信服我真的做过。

### 三个核心目标

1. **可信度**：每个能力项都能点进去看到代码 / 报告 / 缺陷证据，不是自吹
2. **易修改**：内容与代码分离，改文字 = 改一个数据文件，不需要动组件
3. **长期可复用**：这次是「实习版」，后续校招版 / 社招版只是换内容、不重做站

### 目标读者与浏览路径

| 读者 | 停留时长 | 他最想看什么 | 网站要给他 |
| --- | --- | --- | --- |
| HR / 初筛 | 20-30 秒 | 你是谁、什么岗、怎么联系 | 首屏：姓名 + 岗位 + 学校 + 联系方式 + 简历下载 |
| 测试组长 / 面试官 | 3-5 分钟 | 你真做过什么、深度如何 | 项目详情页：架构图、设计取舍、缺陷证据 |
| 技术总监 | 1-2 分钟 | 工程素养、思维水平 | 「测试设计原则/数据治理」这类体现方法论的内容 |

**关键洞察**：你最大的差异化资产不是「会 Selenium」（人人都会），而是
**README 里体现的方法论**：过滤验证双侧证据、契约型 vs 记录型断言、禁条件断言、
栈式清理、数据零残留对账。这些是**测试思维的证据**，必须在网站上有独立位置展示。

## 四、技术选型

### 结论：`Astro + TypeScript + Tailwind CSS`，输出纯静态站点

### 为什么是 Astro（对比另外两个候选）

| 方案 | 优点 | 对你的问题 |
| --- | --- | --- |
| Next.js（React） | 生态最大，简历加分 | SSR/路由约定复杂度对**测试岗无加分**，只有踩坑成本 |
| Vite + React（纯 SPA） | 结构简单 | 首屏白屏、SEO 差、需手动配 Markdown 解析 |
| **Astro（选定）** | 内容用 Markdown 写、构建出纯 HTML、首屏秒开、SEO 好、Vercel 零配置 | 复杂度和收益最平衡，且「内容与代码分离」天然满足你「易修改」的诉求 |

### 为什么这个组合满足你的三个特殊要求

| 你的要求 | 技术上的保障 |
| --- | --- |
| **易于修改**（你要不断加内容） | 所有文字/项目/技能放在 `src/content/` 下的 Markdown 与数据文件里，改内容不碰组件代码 |
| **后续换版本**（实习版→校招版→社招版） | 内容与展示彻底分离：换版本 = 改数据 + 调首页文案，网站骨架复用 |
| **你不懂 AI 和建站** | 全流程我带你做，每步有明确命令；站点是纯静态，没有数据库、没有后端，几乎不会坏 |

### 目录结构（内容与代码分离的设计）

```
front/
├── src/
│   ├── content/              ← ★ 你以后主要改这里
│   │   ├── projects/         ← 每个项目一个 .md 文件，加项目 = 加文件
│   │   ├── skills.ts         ← 技能分组与熟练度
│   │   └── profile.ts        ← 姓名、岗位、联系方式、核心数据、方法论
│   ├── components/           ← 展示组件（一般不用改）
│   ├── layouts/              ← 页面框架
│   └── pages/                ← 路由（首页、项目详情）
├── public/                   ← 头像、简历 PDF、项目截图
└── docs/                     ← 本项目文档（方向确认书等）
```

## 八、内容口径纪律（避免面试翻车）

1. **不写没做过的东西**。技能列表里的每一项，都要能回答「你在哪用过、遇到什么问题、怎么解决」。
2. **熟练度措辞沿用简历口径**：熟练 > 熟悉 > 了解，三者不可混用。
3. **数字必须可复现**：21 接口、35 用例、100%、0 残留，都要是真实数据。
4. **AI 使用如实说明**：你的 README 已经诚实标注了 AI 辅助润色 —— 这个态度本身是加分项，网站保留同样口径。
5. **UI 项目未完成就标「进行中」**，不夸大。面试官对「进行中」的容忍度远高于对「夸大」的。

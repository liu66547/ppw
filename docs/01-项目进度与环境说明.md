## 网址格式约定（别改乱）

全站网址统一 **带结尾斜杠**，例如 `/projects/xzs-api-test/`。

三处保持一致，否则搜索引擎会把同一页面当成多个地址：

| 位置 | 配置 |
| --- | --- |
| `astro.config.mjs` | `trailingSlash: 'always'` + 默认目录输出格式 |
| `vercel.json` | `"trailingSlash": true` |
| 页面 canonical / `sitemap.xml` | 自动生成，均带斜杠 |

**404 页面故意不带 canonical，改用 `noindex, follow`** —— 功能性页面不该被收录。

验收脚本会校验这三者一致，改坏了跑一下就能发现。

### 为什么是 Astro 5 而不是最新的 7

一开始装了最新的 Astro 7.3.8（配 Vite 8），但 `astro build` 直接失败：

```
GenerateContentTypesError: require is not defined
  at eval (.../node_modules/yaml/dist/index.js:6:16)
  at ModuleRunner.directRequest (.../vite/dist/node/module-runner.js:1288)
```

原因是 Astro 7 的内容集合加载器跑在 Vite 8 的 ESM 模块运行器里，而它依赖的 `yaml`、`picomatch`
都是 CommonJS 包，被当作 ESM 执行就炸。试过 `vite.ssr.external` 与 alias 指向 ESM 构建，
修好一个立刻冒出下一个（`yaml` → `picomatch`），属于**逐个打补丁不可维护**的情况。

所以降级到 **Astro 5.18 + Vite 6** 这个久经验证的稳定组合。功能上我们没有任何损失。

## 关于运行环境（曾经的一个坑，已解决）

开发过程中一度遇到过构建失败：

```
spawn EPERM
```

**原因**：当时会话运行在受限沙箱里，而沙箱禁止使用「命名管道」做进程间通信。
Astro 构建要启动的 `esbuild` 恰好就是用管道和 Node 通信的 —— 于是必然撞墙。

**现状**：该限制已解除。当前环境下 `npm run build` 与 `npm run dev` **都能直接跑通，无需任何提权**，
已实测验证。

> 📌 顺带说明：这不是资源占用问题，也不需要你关闭任何程序。
> **你今后在自己电脑的终端里跑，一直是完全正常的。**

另外 `npm install` 若遇到 `EPERM / rmdir` 失败，那是 Windows 文件占用（杀毒软件或编辑器锁定），
彻底删掉 `node_modules` 目录再装即可。

> 补充：安装依赖时如果给 `npm install` 加过 `--ignore-scripts`，那是因为部分包的「安装脚本」
> 同样依赖管道通信。本项目不需要编译原生模块，跳过没有任何副作用。

## 设计决策记录

| 决策 | 理由 |
| --- | --- |
| 内容与代码分离（Markdown + TS 数据文件） | 你要求「易于修改」「后续换版本复用」，改文字不用碰组件代码 |
| 深色科技风（黑底 + 青绿强调） | 你选的风格；青绿呼应「测试通过」的语义直觉 |
| 自定义颜色而非 Tailwind 默认调色板 | 默认蓝紫色系太大众化，深色下对比度也不够 |
| 绿=通过 / 红=失败 / 黄=进行中 | 用测试报告的语义配色，受众一看就懂 |
| 首屏用纯 CSS 动画，滚动区用 IntersectionObserver | 首屏不能等 JS；同时加了 2.5 秒兜底强制显示，避免观察器异常导致内容不可见 |
| 简历下载按钮放首屏第一位 | 招聘方第一诉求是拿到 PDF，其次才是浏览网站 |
| 网址统一带结尾斜杠 | 让 canonical、sitemap、实际地址三者一致，避免搜索引擎重复收录 |
| 404 页用 `noindex` 而非 canonical | 功能性页面不该进索引；用测试报告语义写错误页，保持整站气质 |
| 技术栈降级到 Astro 5 | Astro 7 + Vite 8 的内容集合加载器与 CommonJS 依赖不兼容，逐个打补丁不可维护 |
